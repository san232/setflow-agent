# SetFlow 개발일지

작성 2026-09-15 · 제출 예정 2026-09-16

## 만들게 된 이유

플레이리스트를 만들 때 분위기의 고저차를 직접 배분하는 과정이 반복되어 번거로웠다. 원하는 흐름을 선택하면 곡을 배치하고 그 이유까지 보여 주는 도구를 만들기로 했다. AI 코딩 도구를 활용해 프로젝트를 구현하고, 실행 화면과 자동 테스트를 통해 결과를 확인했다.

## 9월 14일 서버와 정렬 구현

Python 3.12.14 가상환경에 FastAPI, Pydantic, SQLAlchemy, pytest를 설치했다. FastAPI는 요청과 API 문서를, Pydantic은 입력 검증을, SQLite는 로컬 저장을 담당하게 했다. 설치된 의존성 버전은 `requirements-lock.txt`에 기록했다.

정렬 로직은 웹과 DB를 사용하지 않는 `app/domain`에 분리했다. 목표 에너지 차이뿐 아니라 앞 곡과의 밝기·긴장도·밀도 차이, 큰 에너지 도약, 마무리 적합도 등을 비용으로 계산한다. Greedy 방식으로 초기 순서를 만든 뒤 두 위치를 바꾸어 전체 비용이 줄어들면 반영한다. Swap 탐색은 최대 6회이며 같은 입력의 순서와 점수가 재현되도록 했다.

웹 Form과 Agent 도구는 같은 Application 서비스를 사용한다. 도구 이름, 설명, 인자 모델과 Handler를 Registry에 등록하고, 실행기는 검증 결과와 성공·실패를 SQLite 로그로 저장한다. Demo Mode에서는 한국어 문장 패턴으로 사용할 도구를 선택한다. 수치가 빠진 등록 요청은 추가 입력을 받아 처리하고, 명확한 곡 ID와 대화 문맥을 사용해 대상을 정한다.

플레이리스트에는 생성 당시 곡 정보를 snapshot으로 저장했다. 원본 곡을 나중에 고쳐도 예전 결과의 점수와 설명이 달라지지 않게 하기 위한 설계이며 테스트로 확인했다.

## 실제 문제를 해결한 과정

### Python 실행 환경

처음에는 일반 `python` 명령으로 실행할 환경이 잡혀 있지 않았다. 사용 가능한 Python 3.12.14를 확인해 프로젝트 전용 가상환경을 만들고, `.venv\Scripts\python.exe`를 직접 호출하도록 설치·실행 명령을 정리했다. 이렇게 실행에 쓰는 Python과 패키지가 섞이는 상황을 줄였다.

### 한글 출력

테스트 출력에서 한글 경로가 깨지는 현상이 있었다. 출력 인코딩을 UTF-8로 맞추기 위해 `PYTHONUTF8=1`을 설정하고, 명령에서도 `-X utf8` 옵션을 사용할 수 있게 했다. 이후 한글이 포함된 실행 로그를 읽을 수 있었다.

### 다섯 정렬 방식에 대한 잘못된 테스트 가정

처음에는 다섯 Preset의 최종 순서가 모두 달라야 한다고 테스트했다. 그러나 같은 곡 집합에서 완만한 상승과 후반 폭발형은 같은 순서를 만들 수 있었다. 두 곡선 모두 상승형이라는 점을 고려해, 다섯 목표 곡선의 차이를 확인하고 여러 정렬 결과가 나오는지를 검사하도록 테스트를 고쳤다. 정답으로 삼은 가정부터 검토해야 한다는 사례였다.

### JSON 다운로드 처리

Blob 방식의 웹 다운로드에서 자동화 도구가 다운로드 이벤트를 확인하지 못했다. 서버 파일 응답과 직접 다운로드 링크는 동작했으므로, 버튼이 서버 다운로드 URL을 사용하도록 바꿨다. 변경 후 브라우저에서 다운로드 동작을 다시 확인했다.

### 서버 실행 포트

8000 포트에서 WinError 10013이 발생했다. 실행 포트를 8765로 바꾼 뒤 Uvicorn 기동과 브라우저 접속을 확인했다. 설치법에도 실제 동작을 확인한 포트를 사용했다.

## 9월 15일 King Gnu 43곡으로 구체화

King Gnu 대표 공연 7개(2019~2025)의 순서를 정리하고, 곡별 장르·악기·편곡 자료를 참고해 43곡의 다섯 초깃값을 채웠다. 원문 제목과 별칭, 본편·앙코르 구분, 각 출현의 위치를 자료에 남겼다.

공연 마지막에 놓인 곡이 항상 조용한 곡은 아니다. 그래서 에너지와 마무리 적합도를 분리했다. 에너지는 음악 기본값 85%와 공연 배치 15%, 마무리는 음악 기본값 55%와 종료 배치 45%로 보정한다. 이 비율과 값은 프로젝트의 주관적 설계이며, 상세 공식은 [조사 문서](KING_GNU_DATA.md)에 있다.

초깃값을 다시 불러와도 사용자가 편집한 값을 덮어쓰지 않도록 했다. 웹의 곡별 펼침 화면에서 장르·악기·근거 링크를 확인하고, 43곡을 사용한 생성 결과와 로그를 검증했다.
