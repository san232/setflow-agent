# SetFlow 제출 전 확인표

**제출 예정일 2026년 9월 16일**

현재 결과보고서는 블로그 게시 URL과 후기 확인란을 남긴 **초안**이다. 학교 양식의 다섯 항목을 채우고 코드·개발 문서·현재 실행 자료를 준비했다.

GitHub 저장소: [san232/setflow-agent](https://github.com/san232/setflow-agent)

## 제출물과 파일

| 제출물 | 준비된 내용 |
|---|---|
| 결과보고서 DOCX | 학교 원본 양식의 표·다섯 항목 순서 유지, 인적사항·코드·캡처·개발 과정·후기 |
| 개발 과정 문서 | README, DEVELOPMENT_LOG.md, CODE_EXPLANATION.md, VALIDATION.md |
| 실사용 후기 | USER_REVIEW.md에 실제 제공한 경험 반영 |
| 블로그 또는 SNS | BLOG_DRAFT.md에 게시용 글 작성 |
| 프로젝트 ZIP | 주요 코드·README·데이터·문서·현재 캡처·테스트 기록 |

## 여섯 평가 기준의 근거 위치

| 평가 기준 | 대응 자료 |
|---|---|
| 주제에 맞는 에이전트 서버 구현 | 보고서 1번, app/tools·agent·domain |
| 실행 완성도와 문제 해결 | 43곡 실행 캡처, VALIDATION, 테스트 stdout/XML |
| 개발 과정·사용 방법 정리 | 보고서 2번, README·DEVELOPMENT_LOG |
| 직접 사용한 후기 | 보고서 3번, USER_REVIEW |
| 블로그 또는 SNS 게시 | BLOG_DRAFT 및 보고서 4번 URL 칸 |
| GitHub 정리·게시 | 코드·README·docs 및 보고서 5번 URL 칸, 저장소 커밋 이력 |

## 최종본으로 바꾸기 전

- [ ] 본인이 느낀 불편한 점과 개선 희망을 확인한다. 특별히 없다면 그 사실을 본인이 확인해 적는다.
- [ ] 블로그/SNS 게시물의 실제 제목과 URL을 보고서 4번과 게시 글 끝에 넣는다.
- [x] GitHub 실제 저장소 URL을 보고서 5번과 게시 글 끝에 넣었다.
- [x] GitHub에서 코드, README, docs, 실행 이미지와 커밋 이력을 확인했다.
- [ ] DOCX의 `[본인 확인]`, `[게시 후 입력]`을 채우고 파일명의 `초안`을 `최종`으로 바꾼다.
- [ ] 수정한 최종 DOCX의 모든 페이지를 다시 확인한다.
- [ ] 문서를 수정했다면 ZIP을 다시 생성해 파일 구성을 확인한다.

GitHub에는 공개용 코드·문서·캡처를 게시했다. 인적사항이 들어 있는 학교 결과보고서는 로컬 제출자료 폴더에 별도로 보관한다. 블로그 게시와 학교 제출은 남아 있으며, 실제 게시 전에는 임의의 URL을 넣거나 게시 완료로 표시하지 않는다.
